SYNC POWERBI (sync.py)
----------------------
Repo: keselmf/powerbi-to-sheets
Corre: GitHub Actions, 10am UTC (7am ARG) todos los días
Reporte PBI: Targets 2.0
  URL: https://app.powerbi.com/groups/me/reports/05bb4648-9787-4e97-b857-b1609e42ebe2/9f0e11514488e07f2659

Qué hace:
  1. Abre PowerBI headless con Playwright usando browser state guardado en secret PBI_BROWSER_STATE
  2. Extrae datos de tabla "Targets 2.0" (scroll para ver Q3)
  3. Calcula overperf con rollover: overperf_q = max(0, (fact_q + overperf_q-1) - target_q * 1.10)
  4. Escribe en hoja PowerBI via Apps Script (writePBI)
  5. Escribe instalación diaria en hoja Diario con fecha D-1 (writeDiario)

Campos que extrae:
  - Area (Owned Accounts, weight 20%): target, fact, pct, overperf, pct_overperf × Q1-Q4
  - KA (Key Accounts, weight 30%):     target, fact, pct, overperf, pct_overperf × Q1-Q4
  - pct_anual

Targets hardcodeados (Plan del reporte):
  Area: Q1=$151,245 / Q2=$221,826 / Q3=$282,324 / Q4=$353,000
  KA:   Q1=$124,625 / Q2=$179,149 / Q3=$202,516 / Q4=$250,000

Q1 y Q2 están hardcodeados en el script (ya cerraron, no cambian).
Q3 y Q4 se extraen en vivo con scroll de la tabla.

Secret GitHub Actions:
  PBI_BROWSER_STATE → JSON comprimido con gzip+base64 (browser state de Playwright)
  Para actualizar: cat ~/.powerbi_browser_state.json | gzip | base64 | pbcopy
  Límite de GitHub Secrets: 64KB. El archivo sin comprimir suele ser ~600KB.

ESTRUCTURA DE LA APP (index.html)
----------------------------------
PWA single-file. Responsive: mobile (< 768px) y desktop (≥ 768px).

Secciones mobile (tabs):
  - Todas:     lista de cuentas con filtros
  - Vencidas:  cuentas con fecha de acción vencida
  - Sales:     widget Sales Machine con KPIs de PowerBI
  - Tablero:   métricas de estado del pipeline

Secciones desktop:
  - Panel izquierdo: Sales Machine widget
  - Panel derecho:   lista de cuentas + detalle

Widget Sales Machine (tab Sales / panel izquierdo desktop):
  - Fact anual / Target / Avance (calculado: sum(area_fact_qN) / sum(area_target_qN))
  - Barra de progreso anual
  - Grid 2x2 (mobile) / 4x1 (desktop) con cards por trimestre
  - Cada card: Area y KA con Fact, Target, Real%, Acumulado%
  - Q3 y Q4 clickeables → abre tabla de instalaciones diarias (hoja Diario)
  - Datos cargados en paralelo al init (getPBI + getDiario simultáneos)
  - Cache en localStorage (ajax_cuentas) para carga instantánea en reaperturas
